Play Game Try the Tree Lab Learn the Binary Trees

Every clue splits into 2 leads. 15 clues, 4 levels. Watch the tree light up!

The characters

One victim, five suspects, and one of them is lying. Hover over a card.

How to play

  1. Start at the crime scene. The study of Sharma Haveli is evidence number 1.
  2. Pick a lead. Every evidence has exactly two leads (left and right). Going forward or back costs 1 step.
  3. Open every branch. All 15 pieces of evidence must be opened. Watch the tree and the circle meter on the Play page.
  4. Use your notebook. Some clues point at a suspect. Some clues clear a suspect. The Suspect Board counts them for you.
  5. Then accuse. The police refuse any accusation until 100% of the leads are explored. A wrong name counts as an incorrect accusation.

The rule behind the project

The case can be closed only when lead completeness is 100%. Accusations at 25%, 50% or 75% are refused and written in the log, so you can study how the percentage of explored leads changes the steps and the time. Use Experiment mode on the Play page, then open the Statistics page.

Two versions, one case

The C++ program in cpp_application/ has the real binary tree code. This website is a separate JavaScript version. It does not run C++. It has its own copy of the tree functions so the game and the pictures work in a browser.

        What happened
        
        
        1. Press Search or Insert.
        
        
        A BST works only when the keys can be compared. Evidence is not stored in a BST because evidence ids follow the story, not a sorted order.
        
      
        
    
        

    
        Search race: evidence tree vs BST
        
    
        To find evidence #id in the case tree we may have to visit many nodes (preorder search, O(n)). If the same 15 ids were kept in a BST, we would need at most 4 comparisons (O(h)).

        DSA learning section
        
    
        Full, Complete and Perfect binary trees
        
    
        A binary tree is a tree where every node has at most two children: a left child and a right child. The investigation is one. Below are the words we use in this project. You can test every idea yourself in the Tree Lab.
        

    
        
      
        RootThe top node: the crime scene.
        
      
        LeafA node with no children: a final finding.
        
      
        Internal nodeA node with at least one child.
        
      
        LevelAll nodes at the same depth. The root is level 0.
        
      
        HeightEdges on the longest root-to-leaf path. Our case tree has height 3.
        
    
        

    
        
      
        
        
        Full binary tree
        
        
        
        Definition: every node has either 0 or 2 children, never exactly one.
        
        
          
          
        • Leaves = internal nodes + 1
          • 
          
        • Total nodes = 2 × internal nodes + 1 (always odd)
          • 
        
        
        
        In our case: every evidence gives exactly two leads. Only final findings are dead ends.
        
        
        
      
        

      
        
        
        Complete binary tree
        
        
        
        Definition: every level is full except maybe the last, and the last level is filled from the left with no gaps.
        
        
          
          
        • Node i has children 2i and 2i+1 (array layout)
          • 
          
        • Height = ⌊log2 n⌋
          • 
        
        
        
        In our case: the case file has no holes. Evidence ids 1 to 15 go level by level, left to right.
        
        
        
      
        

      
        
        
        Perfect binary tree
        
        
        
        Definition: every internal node has 2 children and all leaves are on the same level.
        
        
          
          
        • Nodes = 2h+1 − 1
          • 
          
        • Leaves = 2h
          • 
        
        
        
        In our case: height 3 gives 24 − 1 = 15 nodes and 8 final findings. Every finding is exactly 3 leads away from the crime scene.
        
        
        
      
        

      
        
        
        Neither: a skewed tree
        
        
        
        Definition: every node has only one child, so the tree is really a linked list.
        
        
          
          
        • Height = n − 1 (the worst case)
          • 
          
        • Traversals and searches still cost O(n)
          • 
        
        
        
        In our case: it would be one long chain of clues with no choices, so the case does not use it.
        
        
        
      
        
    
        

    
        How the three properties relate
        
    
        
      
        TreeFullCompletePerfect
        
      
        
        Perfect (7 nodes)yesyesyes
        
        
        Complete, last level half filled (6 nodes)noyesno
        
        
        Full with a gap on the last level (5 nodes)yesnono
        
        
        Skewed chain (4 nodes)nonono
        
        
        Sharma Haveli case tree (15 nodes)yesyesyes
        
              
    
        
    
        Every perfect tree is both full and complete, but full and complete are independent of each other. The ticks in the badges above are worked out live by the same JavaScript functions the game uses.
        

    
        The four traversals
        
    
        
      
        
        
        Depth-first (recursive)
        
        
          
          
        • Preorder Root, Left, Right: the way a detective goes deep into one lead first.
          • 
          
        • Inorder Left, Root, Right: gives sorted order in a BST. For the evidence tree it is only a demo.
          • 
          
        • Postorder Left, Right, Root: final findings come before the evidence that led to them.
          • 
        
        
      
        
      
        
        
        Breadth-first (queue)
        
        
          
          
        • Level-order visits level 0, then level 1, then level 2 and so on: all first leads first, then all second leads.
          • 
        
        
        
        Watch the call stack and the queue work live in the Tree Visualizer.
        
      
        
    
        

    
        Where a Binary Search Tree fits
        
    
        
      
        
        
        A BST keeps smaller keys on the left and bigger keys on the right. This lets us search in O(h) time. It is the right tool for the suspects, who have unique ids. It is the wrong tool for the evidence, because evidence ids follow the story and not a sorted order. Searching the general evidence tree takes O(n).
        
        
        Suspect BST (ids inserted in the order 3, 1, 4, 2, 5). Its inorder walk gives 1, 2, 3, 4, 5. Try inserting more ids in the Tree Lab.
        
      
        
      
        
    
        

    
        Time complexity of the operations
        
    
        
      
        OperationTimeExtra space
        
      
        
        Preorder / inorder / postorderO(n)O(h) recursion stack
        
        
        Level-orderO(n)O(w) queue (w = widest level)
        
        
        Count nodes / leaves, heightO(n)O(h)
        
        
        Search by id in a general binary treeO(n)O(h)
        
        
        Search by id in a BSTO(h), O(log n) if balancedO(h)
        
        
        isFull / isComplete / isPerfectO(n)O(h) or O(w)
        
              
    
        
    
        Theory versus the clock: O(n) says the work grows in proportion to the nodes visited. It does not say how many seconds. Real elapsed time depends on the computer, and for a human player it is mostly reading time. See the Statistics page.

        How to read these numbers
        
      
          
        
        • Steps grow with completeness: more explored leads means more moves, almost in a straight line.
          • 
        
        • Real elapsed time for a 15-node tree on a computer is only a few microseconds, so noise can hide the trend. The scaling experiment on much bigger trees shows the straight-line growth clearly. For a human player, time is mostly reading and thinking.
          • 
        
        • Theoretical complexity (O(k) to visit k nodes, O(n) for all of them) tells how the work grows. It is not a measurement in seconds.
          • 
        
        • The accusation is accepted only at 100% in every row, because the game enforces it.
